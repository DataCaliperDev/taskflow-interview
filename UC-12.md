# UC-12 · Testing: Improve Test Suite

## 1) Problem Summary

The test suite had structural quality issues:

- shared mutable state across tests
- order-dependent behavior
- weak assertions (status-only checks)
- missing endpoint scenarios

This reduced reliability and made regressions easier to miss.

## 2) Solution, Trade-offs, and Assumptions

### Solution

- Refactored fixtures toward isolation in `tests/conftest.py`.
- Added DB reset behavior between tests to reduce cross-test coupling.
- Removed global task-id flow; moved to fixture-driven resource creation.
- Strengthened existing tests to assert response body fields, not only status codes.
- Added new coverage scenarios (auth required, invalid input, search, comments, ownership-related behavior, etc.).

### Trade-offs / Assumptions

- Better isolation increases runtime (more setup/teardown).
- Reliability and deterministic behavior were prioritized over speed.
- A stale-token edge case in username-update test was handled by re-authenticating after username change.

## 3) How to Run Tests

Run full suite:

```bash
python -m pytest -q
```

Run only test-suite improvement targets:

```bash
python -m pytest -q tests/test_auth.py tests/test_tasks.py tests/test_users.py
```

Optional with coverage gate:

```bash
python scripts/coverage_report.py --min-percent 80
```
